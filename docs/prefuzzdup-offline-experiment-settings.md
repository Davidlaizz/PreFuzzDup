# PreFuzzDup 离线实验交接设置

更新：2026-10-08。本文覆盖此前文档中“密文不得通过 Git”和“挑战时钟方案待定”的描述，仅适用于用户已授权的本次实验。

## 交接范围

本机为客户端，4110 为服务端。Git 可以交接参考及查询标签、公开协议字段、真实密文和脱敏结果。参考库保留全部 413,921 条标签；本次仅准备实际协议候选并集的 2,259 条参考密文，不强制准备 5,000 份。

密文来自 `prefuzz-encrypted-v1-20261008/artifacts/`，共 14,224,623 字节；`records.csv` 为 1,537,727 字节，包含公开验证键、nonce、认证标签、封装密钥和记录映射。它不包含明文数据密钥或签名私钥。

不得把其父目录整体加入 Git：`private-bodies.tsv` 是正文的十六进制表示，仍属明文。原始邮件、正文、秘密密钥、SQLite 和客户端私有来源清单保持本地。交接工具须按白名单复制并校验 SHA-256，不能强制添加整个忽略目录。

## 有效期与计时

原默认有效期保留 120 秒。`setup` 增加参数：

```bash
./PreFuzzDup/build/prefuzzdup setup \
  --db "$HOME/prefuzz-experiment/state.sqlite" \
  --blob-dir "$HOME/prefuzz-experiment/blobs" \
  --capacity 413921 --fpp 0.01 --threshold text=6 \
  --challenge-ttl-seconds 1728000
```

这是原协议数据库的配置示例，不可用它打开导入器生成的 `protocol_records` 库。两者适配尚未完成，也不能据此宣称全量交接已可运行。

有效期从服务端签发挑战开始，按真实服务器时间检查。20 天内完成签名回传；过期需重新签发挑战。保留用户、记录、查询标签绑定、真实签名校验和一次性消费。配置存储在数据库，重开仍生效；旧库缺少配置时使用 120 秒。

实际标签生成、检索、证明、加解密仍测真实计算耗时。“不真的计时”按不测 Git/人工等待解释，不伪造计算耗时。通信单列为估算：RTT 1 ms、带宽 1 Gbit/s，按实际轮数和消息字节数计算，不能写成实测端到端时间。
