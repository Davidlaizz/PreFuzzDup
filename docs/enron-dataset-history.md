# Enron 数据准备与早期统计记录

以下为 2026-09-20 数据准备阶段的历史记录，不代表当前实验状态。2026-09-21 已确认 5w 与全量标签检索实验完成；尚未完成全量独立文本近似分类或两机端到端实验。

## Enron 语料与统计口径

以下为 2026-09-20 的本地探测记录。后续修改预处理规则或重新统计时，应同步更新口径与结果，不把历史结果当作自动成立的当前状态。

- 来源：CMU Enron Email Dataset，2015-05-07 版本；本地压缩包为 `enron_mail_20150507.tar.gz`，解压邮件位于 `enron_mail_20150507/maildir/`。
- 原始语料、压缩包和 `results-local/` 均已被 `.gitignore` 排除，不应强制加入 Git。下列报告和脚本是本地分析产物，克隆仓库后不保证存在。
- 已完成的是**全量正文精确查重、早期 5,356 篇抽样近似配对探测，以及 51,740 篇十分之一抽样数据集（5wTest）的标签准备与样本内真实相似度统计**；尚未完成全量近似分类，也不是三套算法的完整 Enron 实验。
- 正文处理：按第一个空行去除外层邮件头，统一 CRLF 换行并去掉正文首尾空白；保留正文内部的引用、转发信息和签名，未做 MIME 解码。

### 全量精确查重结果及来源

| 指标 | 数值 | 含义 |
| --- | ---: | --- |
| 邮箱目录 | 150 | 邮箱导出目录，不等同于发件人数量 |
| 邮件正文 | 517,401 | 全量扫描的邮件文件数量 |
| 不同正文 | 247,872 | 按上述处理口径得到的正文 SHA-256 种数 |
| 额外重复副本 | 269,529 | 每种正文保留一份后的剩余数量，约占全部文件的 52.09% |
| 重复正文组 | 132,046 | 正文出现次数大于 1 的组数，不是副本数或配对数 |

来源为 `results-local/enron-probe/body-only.json` 的 `body_files`、`unique_bodies`、`extra_exact_body_copies` 和 `exact_duplicate_groups` 字段；早期 `probe.json` 的正文统计也得到相同结果。

计算代码在 `results-local/enron-probe/body_only.py`：对全部正文累计 `body_counts[sha256(body)] += 1`；不同正文数为 `len(body_counts)`；额外副本数为 `sum(count - 1)`；重复组数为 `sum(count > 1)`。因此 `247,872 + 269,529 = 517,401`，而 `132,046` 是独立统计的重复组数量，不由抽样推算。

全量计数时在内存中记录了各正文哈希的频次，但没有持久化完整的逐组频次和成员路径映射。现有报告仅保留汇总与少量配对示例，不能据此列出所有“哪封与哪封重复”。如果需要，应另行输出正文哈希、组内总数、额外副本数、邮箱及原文件路径明细。

### 抽样配对结果及边界

正文近似探测每个邮箱最多抽样 40 封，筛选至少含 20 个 ASCII 字母数字词的正文，得到 5,356 篇。仅用正文五词片段召回候选，不用外层主题或收发件人判定相似。

| 配对来源 | 总对数 | 正文完全相同 | 可能相似 | 低文本重合 | 待定 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 正文候选对 | 43,079 | 332 | 728 | 39,965 | 2,054 |
| 随机对 | 10,000 | 0 | 0 | 9,993 | 7 |

规则：先检查正文 SHA-256，相同时核对字节；其他邮件对使用五词片段 Jaccard，`>=0.5` 为可能相似、`<0.1` 为低重合，中间保留待定。这些是探索性阈值，不是已校准的语义真值或 SimHash 阈值。

上述单位为**邮件对**。同一邮件可与不同邮件形成不同类别，两种配对来源也不保证互斥；不能把它们相加当作独立邮件数量，不能外推全库类别比例。候选召回并不穷尽所有样本对。“低文本重合”不等于语义完全无关。

报告为 `results-local/enron-probe/body-only-report.md`，详细统计、方法及示例在同目录 `body-only.json`。早期 `probe.json` 的同主题候选统计采用另一套召回方法，不要与此表混用。

### 十分之一抽样数据集（5wTest）

2026-09-20 生成，位于 `enron_mail_20150507/5wTest/`。抽样方法：枚举 `maildir/` 下全部 517,401 封邮件，按相对路径排序，用固定随机种子 `20260920` 无放回均匀抽取 51,740 封；不做预去重，保留自然重复；样本按来源路径排序后编号 `enron_000001` 至 `enron_051740`。

正文处理沿用全量统计口径（CRLF 统一为 LF、按第一个空行去除外层邮件头、去首尾空白、不做 MIME 解码）。短正文和重复正文均保留；文件无法读取或缺少头／正文分隔符时工具直接报错中止，不跳过或补抽。

标签为 256 位 PreFuzzDup 文本 SimHash：只保留 ASCII 字母数字并转小写；使用连续三词特征（`0x1f` 连接）；不足三词时严格沿用现有实现，仅使用第一个词；无有效词时使用 `empty`；域标识 `PreFuzzDup/tag/text/v1` 与特征分别按 4 字节大端长度前缀编码后 SHA-256；按字节内 LSB-first 位序投票，`score >= 0` 置 1（零票置 1）；输出为 64 个小写十六进制字符。

| 指标 | 数值 |
| --- | ---: |
| 样本邮件 | 51,740 |
| 唯一正文 | 46,062 |
| 额外精确重复副本 | 5,678（约 10.97%） |
| 精确重复组 | 4,394 |
| 无有效词正文 | 3 |
| 规范化词数总计 | 14,880,744 |

样本内重复率低于全库 52.09% 是均匀无放回抽样的自然结果：多数重复副本的搭档未被同时抽中；未对样本做任何比例调整。

输出文件：`bodies/<id>.txt`、`tags.csv`（`id,type,tag_hex`，type 均为 `text`，供三套检索程序共同使用）、`manifest.csv`、`dataset.json`、`README.md`，另有 `cpp_verification.json`、`edge_cases.csv`、`prepare_summary.json` 校验证据。生成与分析工具位于 `results-local/enron-5w/`（`prepare_dataset.py`、`verify_tag.cpp`、`analyze_similarity.py`），报告为同目录 `similarity-report.md` 和 `similarity-stats.json`。数据集和工具均被 `.gitignore` 排除。

验证状态：独立 C++ 校验器通过包含 `PreFuzzDup/src/main.cpp` 直接调用现有 `make_tag`，边界用例 9/9（空文本、一词、两词、三词、四词、大小写、标点、换行、非 ASCII 字节）与全部 51,740 个正文标签逐字节一致；全部正文重新读取并核对 SHA-256 与字节数；样本、正文、清单、标签记录均为 51,740 且编号唯一；CSV 为无 BOM UTF-8、LF 换行。该阶段未划分参考库与查询集、未建立数据库、未运行三套算法性能测试。

### 5wTest 真实相似度统计

真值判定不使用 SimHash：完全相同正文按正文 SHA-256；非相同正文按五词片段 Jaccard，`>=0.5` 为可能相似、`<0.1` 为低文本重合、中间为待定。注意 SimHash 标签使用三词特征，与本节真值分析的五词片段是两套不同度量，不得混用。

按邮件数口径（每封按“存在完全相同正文 → 无完全相同但发现可能相似 → 未发现相似”优先级判定）：

| 类别 | 邮件数 | 占比 |
| --- | ---: | ---: |
| 存在完全相同正文 | 10,072 | 19.47% |
| 无完全相同但发现可能相似 | 7,019 | 13.56% |
| 未发现相似 | 34,649 | 66.96% |

其中“存在完全相同”来自全部 SHA-256 重复组，不受召回限制；重复组内完全相同邮件对共 8,922 对。

按邮件对口径（候选召回：每封最多取 12 个稀有共享五词片段，文档频率 <=40；随机对使用同种子 10,000 对作基线）：

| 配对来源 | 总对数 | 完全相同 | 可能相似 | 低文本重合 | 待定 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 正文候选对 | 546,137 | 8,594 | 14,702 | 490,465 | 32,376 |
| 随机对 | 10,000 | 0 | 0 | 10,000 | 0 |

候选对中完全相同（8,594）比 SHA 全量判定（8,922）少 328 对，主要因部分重复正文少于 5 个词，无法形成五词片段参与召回。样本内少于 5 词的邮件 830 封，少于 20 词的 5,319 封；它们的完全相同仍可由 SHA-256 判定，近似召回能力受限。

边界：候选召回不穷尽全部配对；“未发现相似”不是语义无关证明；邮件对与邮件数口径不可互换或相加；以上是样本内统计，不能外推为全库比例，也不是参考库-查询集划分后的查询命中率。

### 重复归因与后续实验

- 正文相同可能来自同邮箱跨文件夹归档、跨邮箱收件／抄送、重复通知等；尚未完成全量归因，不能将 52.09% 解释为抄送比例、80% 内容相似度或存储节省比例。
- `all_documents`、`discussion_threads`、`inbox` 及业务文件夹是归档位置，不是相似度标签。提取时保留邮箱、完整文件夹及原文件路径，以区分同邮箱与跨邮箱重复。
- 若要使类别计数对应查询邮件总数，应先固定参考库和匹配规则，每封查询按“存在完全相同正文 → 无完全相同但有近似正文 → 未找到相似正文”依次判定；边界样本保留待定。该分类不同于邮件对统计。
- 比较三套检索算法时，应统一正文预处理、256 位标签及查询集，并以全扫描核对检索正确性。验证真实文本相似性时使用独立指标及抽查，不用 SimHash 阈值同时生成真值和验证结果；正文近似也不保证模糊秘密恢复及所有权证明成功。
