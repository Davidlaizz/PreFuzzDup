# 三套方案的代码逻辑与数据库说明

本文依据当前仓库源码，梳理 PreFuzzDup、SimLESS 和 FuzzyDedup 的执行流程、检索方法与数据库结构。文中的本地验证状态记录于 2026-09-20，不代表完整论文实验已经复现。

## 1. 总体关系

三套程序均用于加密数据模糊去重实验。这里的 FuzzyPoW 指“模糊所有权证明”，用于验证用户是否拥有相关内容。

| 方案 | 主程序职责 | 检索方法 | 持久化存储 |
| --- | --- | --- | --- |
| PreFuzzDup | 本地上传、查重、证明、加密存储、引用绑定 | Prefix Filter＋分段倒排索引 | SQLite 元数据＋磁盘密文 |
| SimLESS | 属性访问控制、配对证明与加解密实验 | 扫描全部标签 | 检索程序使用 SQLite |
| FuzzyDedup | 模糊密钥恢复、OT 抽样证明与加解密实验 | 汉明重量筛选＋分段提前终止 | 检索程序使用 SQLite |

PreFuzzDup 实现了本地上传与复用流程；SimLESS、FuzzyDedup 的主入口以固定样例自测和密码学微基准为主，另有独立检索程序。三套代码都不是完整的网络云存储服务。

两个对比项目通过各自的 `prefuzzdup_core.cpp` 复用基础实现，并保留独立构建能力。该文件含有存储相关代码，但其原入口被重命名，不意味着对比项目的 `self-test` 或 `benchmark` 会执行 PreFuzzDup 上传流程。

## 2. PreFuzzDup

### 2.1 主程序与上传流程

入口：[PreFuzzDup/src/main.cpp](../PreFuzzDup/src/main.cpp)。支持 `setup`、`upload`、`bulk-upload`、`list-refs` 和 `self-test`。

一次上传按以下步骤执行：

1. **生成相似性标签。** 读取文件；文本使用 SimHash 生成 256 位标签。两个标签中不同位的数量称为汉明距离。
2. **查询候选。** 按配置阈值分段，先经过内存 Prefix Filter，再访问 SQLite 倒排索引，取得候选记录。计算完整标签距离，保留阈值内的候选并按距离排序。
3. **执行所有权证明。** 使用上传文件的恢复特征与候选记录的辅助数据，通过模糊提取器尝试恢复相同秘密；经 HKDF 派生 Ed25519 签名密钥，对服务器的一次性挑战签名并验证。
4. **成功时复用。** 解开候选记录中的密钥封装，解密代表文件并复核标签及恢复秘密，然后写入用户引用关系。
5. **无法复用时首次存储。** 随机生成文件密钥，用 AES-GCM 加密文件，再封装文件密钥；将文件密文写入磁盘，将记录、倒排项与引用写入数据库。

对应核心函数为 `Server::candidates()`、`fuzzy_pow()`、`recover()`、`first_upload()` 和 `Server::bind()`。

标签接近只是进入验证流程的条件，不直接代表允许复用。复用成功时恢复的是已存储的代表文件；当前代码不保存相似版本的差异，不保证逐字节恢复每个上传版本。

### 2.2 检索原理

若允许最多 `t` 位差异，将标签分为 `t+1` 段，则阈值内的两个标签至少有一段完全相同。倒排索引用这些相同片段召回候选，再通过完整距离计算排除误匹配。

[prefix_filter.hpp](../PreFuzzDup/src/prefix_filter.hpp) 实现两级 Prefix Filter。它在查询倒排表之前排除确定不存在的片段，减少无效数据库访问；“可能存在”仍需继续验证。备用表使用精确内存字典，未采用论文中的 SIMD 压缩实现。

独立基准入口：[persistent_lookup.cpp](../PreFuzzDup/src/persistent_lookup.cpp)。它读取标签 CSV，不执行文件加密或所有权证明。

| 策略 | 查询流程 |
| --- | --- |
| `scan` | 扫描同类型记录，逐个计算完整标签距离 |
| `exact` | 直接查询分段倒排索引，再计算完整距离 |
| `prefuzz` | 先用 Prefix Filter 过滤，再查倒排索引和计算完整距离 |

`exact` 指片段的精确索引查询，并非只匹配完全相同的文件。三种策略均返回阈值内候选集合，`--verify-equivalence` 检查集合是否一致。

### 2.3 上传数据库

SQLite 文件由 `--db` 指定，例如 `server.sqlite`，包含五张表：

| 表 | 主要字段 | 用途 |
| --- | --- | --- |
| `meta` | `k`、`v` | 容量、过滤器参数、类型阈值等配置 |
| `records` | `rid`、`type`、`tag`、`helper`、`vk`、`cipher_path`、`wrap` 等 | 代表文件标识、标签、恢复辅助数据、公钥、密钥封装及密文路径；另存随机数和认证标签 |
| `postings` | `type`、`seg`、`value`、`rid` | 文件类型、分段位置及片段值到代表文件的倒排映射 |
| `refs` | `uid`、`rid`、`created` | 用户引用的代表文件 |
| `challenges` | `token`、`uid`、`rid`、`query_tag`、`expires`、`used` | 一次性挑战的绑定关系、有效期及使用状态 |

文件密文位于 `--blob-dir` 指定的目录，数据库保存其路径。Prefix Filter 位于内存，启动时根据持久化记录重建。

### 2.4 检索实验数据库

独立检索程序使用另一套 SQLite 表结构：

| 表 | 主要字段 | 用途 |
| --- | --- | --- |
| `index_meta` | `key`、`value` | 输入文件、标签长度与阈值对应的索引签名 |
| `records` | `record_id`、`type`、`tag` | 完整标签 |
| `postings` | `type`、`segment`、`value`、`record_id` | 分段倒排索引 |

输入和参数满足复用条件时，程序复用已有磁盘索引；否则重建。内存 Prefix Filter 每次启动重新建立。索引准备时间单独统计，不包含在逐条查询时延内。

**上传数据库与检索实验数据库必须使用不同文件。** 两者虽都有 `records` 和 `postings` 表，但字段结构不同。

## 3. SimLESS

### 3.1 密码学主流程

入口：[SimLESS/src/main.cpp](../SimLESS/src/main.cpp)。提供 `self-test` 和 `benchmark`，核心函数为 `run_once()`。

1. 初始化双线性对参数、属性集合与密钥材料。
2. 按合取属性策略执行 CP-ABE 风格的密钥封装与恢复，例如要求同时具有 `researcher` 和 `project-x` 属性。
3. 对固定测试文本执行模糊秘密生成与恢复。
4. 根据恢复秘密构造多项式及承诺，执行双线性对 FuzzyPoW 验证。
5. 使用密钥完成 AES-GCM 加解密并验证结果。

基准输出属性加密、属性解密和证明的耗时。自测还检查属性不满足策略时是否被拒绝。上述流程在内存中运行，不建立用户、文件或引用关系数据库。

### 3.2 检索流程

入口：[SimLESS/src/lookup_benchmark.cpp](../SimLESS/src/lookup_benchmark.cpp)，运行时使用 `--scheme simless`。

程序读取外部标签数据并写入 SQLite。每次查询读取全量标签块，对每个标签计算完整汉明距离，求出最小距离，再判断是否满足阈值。它不采用 Prefix Filter 或分段倒排召回。

## 4. FuzzyDedup

### 4.1 密码学主流程

入口：[FuzzyDedup/src/main.cpp](../FuzzyDedup/src/main.cpp)。提供 `self-test` 和 `benchmark`，核心函数为 `run_once()`。

1. 对固定测试文本分别生成检索标签和密钥恢复特征，二者采用不同的域标识。
2. 经模糊提取器恢复秘密，并使用 HKDF 派生密钥。
3. 当前原型通过伪随机字节流与明文异或实现加解密。
4. 抽样选取存储密文与声明密文的比特位置，通过 1-out-of-2 不经意传输（OT）累计差异、估计距离。
5. 检查证明结果，解密并确认恢复内容。

基准输出 OT 次数、协议字节数和耗时；自测还检查明显错误的所有权声明是否被拒绝。该主流程在内存中执行，不创建业务数据库。

### 4.2 检索流程

入口：[FuzzyDedup/src/lookup_benchmark.cpp](../FuzzyDedup/src/lookup_benchmark.cpp)，运行时使用 `--scheme fuzzydedup`。

- **重量筛选：** 标签中 `1` 的数量称为汉明重量。查询标签重量为 `w`、阈值为 `t` 时，只读取重量位于 `[w-t, w+t]` 范围内的标签块，因为重量差已经是汉明距离的下界。
- **三段比较：** 对候选标签分三段累计距离，超过阈值即停止该候选的比较。
- **命中返回：** 找到一个符合阈值的标签即返回成功，不继续枚举所有匹配。

## 5. 两个对比方案的检索数据库

SimLESS 和 FuzzyDedup 的检索程序使用相同的 `PersistentLabelTable` 结构，可分别通过 `--db` 指定 `simless_labels.sqlite` 与 `fuzzydedup_labels.sqlite`。

| 表 | 字段 | 含义 |
| --- | --- | --- |
| `label_blocks` | `kind` | `all` 表示全量块，`weight` 表示重量分组块 |
| `label_blocks` | `weight` | 标签重量，和 `kind` 组成主键 |
| `label_blocks` | `tags` | 多个 256 位标签拼接成的二进制数据 |

建库时同时写入全量标签块和按重量分组的标签块。SimLESS 读取 `kind='all'` 的块；FuzzyDedup 读取重量范围内的 `kind='weight'` 块。

每次启动该检索实验都会执行 `DROP TABLE IF EXISTS label_blocks` 并重新导入输入数据，不复用之前的标签表。应使用专门的实验数据库文件。

SQLite 页缓存设置约为 1 MiB，但这不等于进程总内存限制，也不限制查询返回的二进制标签块大小。两者均关闭 SQLite 日志和同步写入，而 PreFuzzDup 使用 WAL 与 `synchronous=NORMAL`；这些是实验实现中的差异。

## 6. 比较结果时的口径

三种检索路径的输出目标不同：

| 路径 | 返回目标 |
| --- | --- |
| PreFuzzDup 检索基准 | 阈值内全部候选集合 |
| SimLESS 检索基准 | 扫描全部标签得到最小距离，并判断是否匹配 |
| FuzzyDedup 检索基准 | 找到首个阈值内匹配即返回 |

因此，查询耗时不能直接解释为相同输出任务下的速度差异。实验应明确是比较“是否存在匹配”“最小距离”还是“全部候选”。单独的标签检索耗时不包含文件加密、所有权证明或密文写入开销。

## 7. 本地数据库与验证状态

### 当前状态（2026-09-21）

5w（51,740 条）和全量（517,401 条）标签检索实验已完成，参考库分别为 41,392 和 413,921 条，均采用 1,000 条查询、3 次重复、阈值 4/5/6。已执行 PreFuzzDup 候选集合等价抽查及跨方案匹配判定一致性检查。数据库与原始证据保存在本地实验目录或 WSL scratch，不随 Git 分发。

这些实验不包含网络、加密、所有权证明和密文写入。尚未实现两机通信，也未完成完整数据集的端到端协议实验；标签检索数据库不能代替上传业务库。
